# Dashboard 现状 vs 建议 对比

---

## 现有内容 → 建议处置

### 现有：欢迎区（标题 + 时间 + 快速创建/刷新）
- **建议**：保留，基本每个 Dashboard 都有

### 现有：4 个指标卡片（总用户、组织、应用、活跃会话）
- **建议**：全部保留 ✅
- **增加**：待处理邀请数（邀请制系统的重要指标，现在没有）

### 现有：系统监控
| 现有子项 | 建议 |
|---------|------|
| 网络状态（下载/上传/延迟） | 看情况保留，优先级低于硬件指标 |
| CPU/内存/硬盘（折线图） | ✅ 保留，但建议改为粗进度条（你之前选的） |
| 系统信息（版本/数据库/Redis/运行时间） | ✅ 保留版本/数据库/运行时间 |
| 节点信息（主机名/IP/OS/状态） | ❌ 移到系统设置页面，Dashboard 不需要 |

### 现有：系统提示（性能优化/安全状态/数据备份）
- **问题**：全是静态文字，没信息量
- **建议**：改为动态告警区 — 正常时不显示（或只显示"系统正常"），有异常时才弹出具体告警

### 现有：快速操作（用户管理/邀请用户/组织架构/角色权限）
- **建议**：✅ 保留全部
- **增加**：应用管理入口（现在缺了这个）

### 现有：最近活动（6 条动态）
- **建议**：✅ 保留

### 现有：底部信息（最后更新/系统状态/版本）
- **建议**：✅ 保留，简单的状态栏

---

## 建议新增（现在没有的）

| 新增项 | 理由 |
|--------|------|
| Logto 服务状态 | 你管理的是 Logto 系统，它在线不在线是最重要的信息 |
| 系统负载趋势图 | 唯一的主图表，显示负载随时间的变化，帮管理员发现高峰时段 |
| 待处理邀请数 | 邀请制系统，这是管理员需要跟进的事项 |
| 应用管理快捷入口 | 5 个核心功能应该都有入口 |

---

## 总结

| 类别 | 操作 | 具体内容 |
|------|------|---------|
| 不变 | 欢迎区、4 指标、活动流、底部栏 | — |
| 小改 | 系统监控 | 去掉节点信息，折线图改进度条 |
| 替换 | 系统提示 → 动态告警 | 静态文字变条件显示 |
| 新增 | Logto 状态、负载趋势图、待处理邀请、应用管理入口 | 4 项 |
| 移走 | 节点信息 | → 系统设置页面 |
