## 🐳 Logto 环境（Docker）

### 启动

```bash
cd deployment/logto
docker compose up -d
# 健康检查
curl http://localhost:3003/api/status   # → 204
```

**要点**（实测确认，见 [SSO平台实施方案.md](SSO平台实施方案.md) 0.4）：

- compose 的 entrypoint 必须为 `npm run cli db seed -- --dapc && npm start`（镜像默认 CMD 不做初始化；`--dapc` 禁用离线环境会卡死的 pwned-passwords 检查）
- 全新库若报 "undeployed database alterations"，说明 seed 没跑过 — 检查 entrypoint
- 镜像拉取慢/超时时使用镜像源：`docker pull docker.m.daocloud.io/svhd/logto:latest` 后 `docker tag` 回原名

## 🔑 Management API 访问（★ 重要修正）

> **⚠️ 实测发现 F1**：旧文档的 `LOGTO_MANAGEMENT_API_KEY` 静态密钥方式**不成立** — Logto 要求 **M2M client credentials 动态换 token**（约 1h 过期，需缓存与刷新）。批次 1 的 LogtoAdapter 将内置 token 管理器。

### 工作原理

```bash
# 1. token 交换 —— 注意走 admin 租户端点 :3002（不是 :3003）
curl -X POST http://localhost:3002/oidc/token \
  -d "grant_type=client_credentials&client_id=<M2M_APP_ID>&client_secret=<M2M_APP_SECRET>&resource=https://default.logto.app/api&scope=all"

# 2. 用返回的 access_token 调 default 租户 Management API
curl http://localhost:3003/api/organizations -H "Authorization: Bearer <token>"
```

### 凭据来源（两条路径）

| 路径 | 适用 | 说明 |
|------|------|------|
| **seed 内置 `m-default`** | 开发/POC | seed 自动创建（admin 租户），secret 从数据库读取：`docker exec logto-logto-db-1 psql -U logto -d logto -t -A -c "SELECT secret FROM applications WHERE id='m-default';"` |
| **专用 M2M 应用** | 生产 | 运营方在 admin console（:3002）创建 M2M 应用并授予 Management API 权限 `all` |

## ⚙️ 后端环境变量（backend/.env）

```bash
cp backend/.env.example backend/.env
```

### 当前生效项

| 变量 | 必填 | 说明 |
|------|------|------|
| `LOGTO_MANAGEMENT_API_ENDPOINT` | 是 | `http://localhost:3003/api`（default 租户） |
| `LOGTO_MANAGEMENT_API_KEY` | 是* | ⚠️ 现有代码的静态密钥假设（F1 缺陷）；批次 1 改为 M2M 凭据后移除 |
| `DATABASE_TYPE` | 是 | 开发 `sqlite`（零配置）/ 生产 `postgresql`、`mysql` |
| `DATABASE_URL` | 条件 | SQLite: `file:./dev.db`；或完整连接 URL |
| `JWT_SECRET` | 是 | `openssl rand -base64 32` 生成 |
| `APP_PORT` | 是 | 3001 |
| `FRONTEND_URL` | 建议 | `http://localhost:3000`（CORS） |
| `REDIS_*` / `MAIL_*` | 可选 | 缓存 / 邮件（邀请功能批次 3 需要） |

### 批次 1 计划新增

## 🚀 生产环境建议

- Logto：独立部署（compose 或云），HTTPS，`ENDPOINT`/`ADMIN_ENDPOINT` 指向真实域名
- 数据库：PostgreSQL 15+（扩展库），切换 `DATABASE_TYPE=postgresql` + 连接串
- 密钥：`JWT_SECRET`/M2M 凭据用密钥管理系统，不入库不入 git
- 邮件：SMTP 生产实例（邀请功能依赖）

## 🔧 故障排查

| 症状 | 原因与解法 |
|------|-----------|
| Logto 容器反复退出，日志报 "undeployed database alterations" | 全新库未 seed — 确认 entrypoint 含 `npm run cli db seed -- --dapc`；必要时 `docker compose down -v` 重置数据卷 |
| 首次创建 admin 用户时卡住 | pwned-passwords 检查无法访问外网 — seed 时加 `--dapc` |
| `docker pull` 超时 | Docker Hub 直连受限 — 走镜像源（daocloud 等）后 retag |
| M2M token 交换返回 `invalid_client` | 端点用错：必须走 **admin 租户 :3002**/oidc/token，不是 :3003 |
| 授权后拿不到 refresh token | 授权请求缺 `prompt=consent`（F2：否则 offline_access 被静默丢弃） |
| refresh token 用一次就失效 | 正常行为（F3：RT 每次轮换），保存响应中的新 RT |
